## 1. リード(なぜこれを作ったか)

公開しているページの内容と、手元で管理している実データが少しずつずれていく問題は、更新を人手で反映する運用にしている限りどこでも起こる。ずれに気づくきっかけが「誰かが偶然見つける」しかないと、古い情報がそのまま外に出続ける。この「ずれをどう自動で検知するか」を、Claude API を使って0から実装してみる。

## 2. ざっくりとしたアーキテクチャ

- 実データ側(source of truth となる構造化データ)と、公開ページ側(実際にレンダリングされた内容)をそれぞれ取得する
- 双方を Claude に渡し、単純な文字列比較ではなく意味レベルで「食い違っている項目」を抽出させる
- 検知結果を差分レポートとして出力する(将来的には Slack 等への通知を想定するが、今回はレポート生成までを実装範囲とする)

## 3. 実装ステップ(コード中心)

Day 2 で以下を実装する予定:

- 公開ページの取得・構造化抽出パート
- source of truth データの読み込みパート
- Claude API による意味レベルの差分判定パート(単純 diff ではなく「同じ意味か」を判定させる設計にする理由も含めて書く)
- 差分レポートの出力フォーマット

## 4. 思考プロセス(自然に織り込む)

最初は単純なテキスト diff で十分ではないかと考えたが、表記ゆれ(全角/半角、敬語の言い回し変更など)まで「ずれ」として拾ってしまい、本当に見てほしい変更点が埋もれる。意味レベルでの比較が必要になった経緯を Day 2 で具体的に書く。

## 5. データアナリスト視点(必須)

実データと公開面の突き合わせは、データ基盤における「マスタと出力先の整合性チェック」と同じ構造の問題として捉えられる。この視点を Day 2 の本文で 2〜3 文にまとめる。
